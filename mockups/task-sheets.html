Session sheets — native bottom sheets

Every Radix Dialog becomes a @gorhom/bottom-sheet slide-up over a dimmed calendar (migration doc Phase 5). Ports frontend/src/components/tasks/create-task-dialog.tsx + edit-task-dialog.tsx + use-task-form.ts; fields match the zod schema in frontend/src/utils/tasks.ts (title · duration 15-min steps · deadline · tags · note). Duration uses a thumb-friendly stepper/slider instead of the web's drag handles; placement is fully automatic, and an unplaceable task surfaces as a non-blocking conflict toast, not a blocking decision sheet. Description drops the web's docked toolbar for a selection bubble that floats above text you've selected instead — same full tool set as components/common/editor/toolbar.tsx (Bold · Italic · Underline · Highlight · Blockquote · Link · file upload · Bullets · Numbering), see the "Edit · populated" frame below. A Sessions stepper (mobile-only — DLU thesis-scope §3.4, mobile issue #33) sits right after Duration for "how many study sessions does this need" — see the dedicated section below. Creating a session, or editing an existing session's deadline, now automatically and transparently repacks that one calendar day's other sessions server-side — no manual trigger, no preview, no undo — surfaced only via a toast alongside the existing placement toast (dayRescheduleToastMessage in lib/task-toasts.ts).

Day reschedule

Creating a session, or editing an existing session's deadline, silently repacks that one calendar day's other pending sessions server-side (EDF + preference-matrix placement, single-day window) — no manual trigger, no diff preview, no undo. The client's only job is a toast when something else moved, composed by dayRescheduleToastMessage in lib/task-toasts.ts; it can stack with the existing placement toast when a create fires both.

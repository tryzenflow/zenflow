Detected-item inbox & push

Mobile-only (docs/thesis-scope.md §4, issue #34) — closes the automatic path: watcher notices something new on a DLU student's LMS/portal → push notification → pre-filled confirm screen → real scheduled task, matching manual creation. A small bell affordance on Day/Week/Month's app bar (not pictured per-screen here — same top-bar chrome as day-view.html, just with a badge) opens the Inbox; tapping a push when the app is foregrounded instead shows a tap-to-act toast over whatever screen is open. Both paths land on the same Confirm screen — styled like app/task/new.tsx's form chrome (not a bottom sheet, since it's reached by a push/deep-link rather than a long-press-on-the-grid). Description renders through description-field.tsx (tentap), same as the create sheet — fully editable, not a read-only preview, so links/formatting carry over instead of showing raw text but the student can still fix them up.
